# Testes automáticos do OmniLifeONE

Rodam no computador, num Chromium de verdade, contra um servidor de arquivos simples (`rodar.js` sobe e derruba sozinho).
Só valores de mentira: nenhuma chave, token ou senha de verdade em código, teste, commit ou conversa.

**Uma vez só** (na pasta do OmniLifeONE):
```
npm install -D playwright
npx playwright install chromium
```

**Para rodar**:
```
node teste/rodar.js
```
Outra porta (se a 8098 estiver ocupada): `PORTA=8096 node teste/rodar.js`. Um arquivo só, com um servidor já no ar:
`BASE=http://localhost:8096 node teste/janelas-omni.js`. Onde o Playwright está instalado em outro lugar: `NODE_PATH=<pasta dos node_modules>`.

**Teste cruzado com o MoneyTRIO** (`aparelhos-cruzado-omni.js`): precisa da pasta do MoneyTRIO (o repositório `investify-me`)
no mesmo computador. Passo a passo:
1. baixe (ou atualize) o MoneyTRIO numa pasta, por exemplo `C:\apps\investify-me` ou `~/apps/investify-me`;
2. na pasta do OmniLifeONE, rode dizendo onde ela está:
   - Windows (PowerShell): `$env:MONEYTRIO="C:\apps\investify-me"; node teste/rodar.js`
   - Mac/Linux: `MONEYTRIO=~/apps/investify-me node teste/rodar.js`
3. o teste abre o MoneyTRIO de lá (só lendo os arquivos: nada é mudado na pasta dele) e o OmniLifeONE daqui, os dois falando
   com o mesmo banco de mentira.

Sem `MONEYTRIO`, esse teste escreve "PULADO" e não conta como falha (o resto da suíte roda igual).

**O SQL de verdade da Parte E** (`sql-giro.js`): roda os dois arquivos `supabase/2026-11-12-*.sql` num Postgres local
(PGlite, em memória) — nada vai para o Supabase, nada é aplicado em banco nenhum. O PGlite **nunca entra no repositório**:
1. numa pasta fora do OmniLifeONE (por exemplo `~/apps/pglite`), rode uma vez: `npm i @electric-sql/pglite@0.2.17`;
2. na pasta do OmniLifeONE: `PGLITE=~/apps/pglite node teste/rodar.js` (Windows/PowerShell: `$env:PGLITE="C:\apps\pglite"; node teste/rodar.js`).

Sem `PGLITE`, esse teste escreve "PULADO" e não conta como falha. As duas variáveis podem ir juntas.
